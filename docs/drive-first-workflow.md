# 개발 자료 보관 원칙

## 원칙

1. 로컬 저장소는 실행 가능한 최소 코드와 작은 문서만 유지한다.
2. `node_modules`, 빌드 결과물, 미디어 원본, handoff zip은 Git 대상에서 제외한다.
3. 다른 컴퓨터에서 이어받을 때는 Git 또는 작은 소스 스냅샷으로 상태를 복원한다.
4. 대용량 자료와 산출물은 별도 클라우드 저장소에 보관하고, 로컬에는 필요한 파일만 내려받는다.

## 이어받기 체크리스트

1. 최신 Git 상태와 `README.md`를 확인한다.
2. 필요한 소스 스냅샷이 있다면 임시 위치에 받고 목록부터 확인한다.
3. 앱 코드와 직접 관련 있는 파일만 작업 폴더로 복원한다.
4. 설치 후에는 `node_modules`와 캐시가 동기화 또는 Git 대상에 올라가지 않도록 유지한다.
5. 작업 종료 시 필요한 경우 작은 handoff 문서를 남기고, 대용량 산출물은 로컬에 남기지 않는다.

## 부분 다운로드와 지속 보관 방식

- 대용량 자료는 전체 복원보다 검색, 목록 확인, 필요한 파일 다운로드 순서로 진행한다.
- 개발 검증을 위해 많이 다운로드해야 할 때는 `/tmp`에 받고, 필요한 코드/작은 자료만 작업 폴더로 옮긴다.
- 앱 코드 백업은 `scripts/make-handoff-snapshot.sh`로 TXT 스냅샷을 만들 수 있다.
- 스냅샷 생성 후 `/tmp/gwalsa-handoff`는 보관 확인 뒤 삭제할 수 있다.
