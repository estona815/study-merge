# DAESIN 제품 계약

- 제품명: 대신 (DAESIN)
- 앱스토어 이름: 대신 – 야식·배달 충동 브레이크
- 문서 상태: Launch MVP v0.1
- 대상 시장: 대한민국, 만 18세 이상
- 오너: Product & Growth
- 기준일: 2026-07-14

## 1. 제품 정의

> 배달앱보다 5분 먼저 열어, 자동 주문 직전의 사용자가 한 번 멈추고 스스로 선택하도록 돕는 AI 충동 브레이크.

대신은 칼로리 기록 앱, 음식 금지 앱, 체중 감량 처방 앱이 아니다. 제품의 성공은 사용자가 음식을 먹지 않았는지가 아니라 **자동으로 주문하지 않고 의식적으로 선택을 완료했는지**로 판단한다.

핵심 브랜드 약속은 `충동 대신, 내가 고른 한 끼.`다.

## 2. 해결할 문제

### 핵심 문제

야식·간식·배달 주문은 배고픔만으로 일어나지 않는다. 스트레스, 심심함, 습관, 노출 자극이 결제까지 짧은 자동 경로를 만든다. 기존 음식 앱은 주로 먹은 뒤 기록하거나 목표 수치와 비교하므로, 결정 직전의 짧고 민감한 순간을 충분히 다루지 못한다.

### 제품 기회

- 사용자가 배달앱을 열기 전 30초 안에 진입할 수 있는 단일 CTA를 제공한다.
- 배고픔과 이유를 최소 입력으로 확인한 뒤, 선악 구분 없는 세 가지 행동을 제시한다.
- 사용자의 실제 선택과 만족도를 다음 추천에 반영한다.
- 먹기로 한 선택도 계획된 자기 결정으로 존중한다.

### 핵심 Job-to-be-Done

> 밤에 무언가를 자동으로 주문하려는 순간, 나를 혼내거나 오래 붙잡지 않으면서 지금 상태를 확인하고 내가 납득할 선택을 하게 도와줘.

## 3. 핵심 고객

### 1차 고객

- 만 18~34세 성인
- 밤에 배달음식이나 간식을 습관적으로 주문하는 사람
- 스트레스·심심함·콘텐츠 노출 뒤 자극적인 음식이 당기는 사람
- 금지와 과식의 반복보다 현실적인 선택 구조를 원하는 사람
- 감정 기록, 다이어리, 캐릭터와 따뜻하고 귀여운 UI를 선호하는 사람

### 행동 세그먼트

| 세그먼트 | 관찰 가능한 순간 | 원하는 도움 | 첫 가치 순간 |
|---|---|---|---|
| 자동 주문형 | 배달앱을 무의식적으로 켬 | 결제 전 짧은 정지 | 세 가지 선택 중 하나를 직접 고름 |
| 감정 자극형 | 스트레스 후 특정 음식이 당김 | 감정과 배고픔을 구분 | 상황 요약이 비난 없이 맞아떨어짐 |
| 제한-반동형 | 오래 참다가 한 번에 주문 | 먹는 선택까지 존중 | 양·사이드·남길 몫을 미리 정함 |
| 루틴 최적화형 | 비슷한 시간과 메뉴가 반복 | 효과 있었던 선택 재사용 | 세이브 메뉴가 다음 추천에 반영됨 |

### 비대상

- 만 18세 미만
- 섭식장애 진단·치료, 영양 처방 또는 응급 지원을 기대하는 사용자
- 체중·칼로리·운동량을 중심으로 정밀 추적하려는 사용자

비대상 사용자를 비난하거나 차단형 카피로 밀어내지 않는다. 의료적 요구에는 서비스 한계를 밝히고 적절한 전문 지원을 고려하도록 안내한다.

## 4. 제품 원칙

1. **먹어도 실패가 아니다.** `대신 먹기`, `계획해서 먹기`, `5분 보류`는 도덕적 우열이 없다.
2. **결정 직전의 속도가 우선이다.** 가입, 긴 설문, 권한 요청은 첫 추천을 막지 않는다.
3. **핵심 개입은 무료다.** 무료 사용자의 충동 세션 수를 제한하지 않는다.
4. **AI가 멈춰도 제품은 멈추지 않는다.** 검증 실패 또는 지연 시 규칙 기반 추천으로 즉시 이어진다.
5. **민감한 순간을 수익화하지 않는다.** 진행 중 세션과 sensitive mode에서는 paywall을 노출하지 않는다.
6. **개인화는 실제 행동에서 배운다.** 말보다 선택, 만족도, 재사용 데이터를 우선한다.
7. **의료·체중 감량을 암시하지 않는다.** 진단, 치료, 식욕 억제, 감량 효과를 약속하지 않는다.
8. **캐릭터는 감시자가 아니다.** 대신이는 결재를 잠깐 보류하는 사용자 편의 작은 비서다.

## 5. 핵심 사용자 여정

### 첫 세션

1. cold launch에서 통계·가입·설문보다 먼저 `Craving Gate`를 연다.
2. 음식 또는 `그냥 뭔가 먹고 싶어요`를 입력하고 게스트 세션을 시작한다.
3. 배고픔 0~10과 가장 가까운 이유 하나를 고른다.
4. AI 또는 규칙 기반 분석 결과와 세 가지 선택을 본다.
5. `대신 먹기`, `계획해서 먹기`, `5분 보류` 중 하나를 고른다.
6. 실제 행동, 충동 변화, 만족도를 짧게 기록한다.
7. 홈의 성장 카드와 기본 주간 리포트에 반영한다.
8. 성인 대상 고지, 추가 선호, 계정 연결과 알림 권한은 음식 입력 시작을 막지 않으며 첫 가치 경험 뒤 필요한 시점에만 요청한다.

`Craving Gate`는 2시간 이내 foreground 복귀에는 반복하지 않고, 진행 중 세션은 이어가며, 기록·설정·레시피 딥링크를 우선한다. 사용자는 설정에서 실행 시 질문을 끌 수 있다.

### 반복 세션

```text
시간대·감정 트리거
  → 지금 땡겨요
  → 30~90초 상태 확인과 선택
  → 결과 기록
  → 효과 있었던 세이브 메뉴·패턴 반영
  → 다음 순간의 더 짧고 적합한 추천
```

## 6. 선택 구조 계약

모든 정상 세션은 정확히 세 가지 선택을 제공한다.

| 선택 | 사용자 약속 | 필수 결과 |
|---|---|---|
| 대신 먹기 | 현재 욕구의 감각을 존중하는 실행 가능한 대안을 본다 | 세이브 메뉴 우선, 준비 시간·감각 태그·3단계 이하 조리법 |
| 계획해서 먹기 | 원래 음식을 먹는 선택을 존중받는다 | 양, 사이드, 남길 몫 중 가능한 계획을 먼저 정함 |
| 5분 보류 | 갇히지 않고 짧게 결정을 미룬다 | 즉시 종료 가능, micro action 1개, 종료 뒤 충동 재확인 |

정렬은 상황에 따라 바꿀 수 있지만 시각적 선악은 만들지 않는다.

- 배고픔 7 이상: 빠른 세이브 메뉴 또는 계획 식사를 앞쪽에 둔다.
- 배고픔 4~6: 세 선택을 균형 있게 제시한다.
- 배고픔 0~3이고 스트레스·심심함·습관이 원인: 5분 보류를 첫 카드로 둘 수 있다.
- 알레르기·식이 제한에 충돌하는 음식은 추천 후보에서 제외한다.

## 7. Launch MVP 범위

### P0 — 출시 전 필수

| 영역 | 포함 범위 |
|---|---|
| 진입 | cold-launch Craving Gate, 최근 음식 칩 최대 3개, 진행 세션·딥링크 우선, 2시간 cooldown, 설정 opt-out |
| 개입 | 음식 입력, 배고픔, 이유, 분석, 구조화 AI, 규칙 기반 fallback |
| 선택 | 대신 먹기, 계획해서 먹기, 5분 보류, 백그라운드 복원 가능한 타이머 |
| 학습 | 결과 기록, 세이브 메뉴, 기본 주간 리포트, 만족도 기반 재추천 |
| 개인화 | 담백·친구·밈, 밈 강도, 테마, 칼로리 숨김, 저자극 보기 |
| 안전 | 알레르기, 식이 제한, sensitive mode, 비의료 안내 |
| 성장 | 선택적 알림, 개인정보 제거 공유 카드, 분석 이벤트 |
| 상용화 | 구독 adapter, 명확한 Paywall, 복원, 데이터 삭제 |
| 운영 | mock mode, 오류 수집 adapter, 오프라인·AI 실패 상태, 테스트·README |

### 가장 작은 완전한 세로형 흐름

`게스트 시작 → 치킨 입력 → 배고픔 6 → 스트레스 → fallback 추천 → 5분 보류 → 충동 재평가 → 결과 저장 → 홈 통계 반영`

이 흐름이 실제 기기에서 데이터 유지와 함께 통과하기 전에는 P0 확장을 완료로 보지 않는다.

### P1 — 현재 구현 제외

- 실시간 음성 AI
- 음식·냉장고 사진 분석
- 편의점 실시간 상품 데이터
- 배달앱 실행 감지, 접근성 서비스 감시, iOS Screen Time 연동
- 위젯
- 운동·물·체중 추적
- 커뮤니티, 친구 경쟁, 웨어러블
- 의료 상담, 코치 마켓플레이스

P1은 Launch MVP의 가격 명분이나 출시 차단 요소로 사용하지 않는다.

## 8. 활성화와 재방문 계약

### 활성화

첫 세션에서 아래 네 단계를 모두 완료하면 활성화로 본다.

1. 음식 입력
2. 상태 확인
3. 행동 선택
4. 결과 기록

단순 앱 실행, 온보딩 완료, 추천 조회만으로 활성화로 계산하지 않는다.

### 재방문 이유

- 최근 효과가 좋았던 세이브 메뉴의 빠른 재사용
- 하루 3~5개의 `오늘의 대신 레시피`와 저장·지금 만들기·관심 없음 피드백
- 사용자가 동의한 시간대의 가벼운 `야식 회의` 알림
- 주간 패턴과 다음 주 제안 1개
- 대신이의 시간대별 메시지와 새 스티커
- 개인정보를 제거한 공유 카드

streak 손실, 실패 배지, 죄책감 알림은 사용하지 않는다.

## 9. Free와 Pro의 제품 경계

- Free는 핵심 개입, 세 가지 선택, 타이머, 기본 기록을 무제한 제공한다.
- Free는 출처·권리·알레르기·영양 신뢰도가 검증된 오늘의 레시피 피드와 기본 개인화를 제공한다.
- Pro는 더 깊은 개인화, 무제한 세이브 메뉴, 상세 패턴, 추가 표현·편의 기능에 과금한다.
- 첫 개입 전, 개입 중, sensitive mode 중에는 paywall을 띄우지 않는다.
- 유료 여부가 추천의 안전성, 알레르기 필터 또는 계획 식사 선택권을 바꾸지 않는다.

세부 상품과 실험은 [MONETIZATION.md](./MONETIZATION.md)를 따른다.

## 10. 안전·신뢰 경계

- 앱은 섭식장애 치료, 의료 서비스, 영양 처방이 아니다.
- 구토, 약물 보상, 장시간 굶기, 과도한 보상 운동, 강한 자기혐오, 자해·자살 신호에는 밈을 끄고 중립적인 안내로 전환한다.
- 사용자가 먹은 뒤 streak를 초기화하거나 벌점을 주지 않는다.
- 민감한 음식명, 감정 메모, 건강 정보는 분석 서비스에 기본 전송하지 않는다.
- 칼로리는 사용자가 켠 경우에만 범위·신뢰도와 함께 접힌 보조 정보로 제공한다.
- 저자극 보기는 사용자별 반응이 다른 표시 옵션이며 식욕 감퇴 효과를 주장하지 않는다.

## 11. 성공·실패 판정

### 제품 성공

- 사용자가 가입 없이 첫 추천과 선택까지 도달한다.
- 먹는 선택을 포함한 세 가지 선택이 동등하게 완료될 수 있다.
- 결과 기록이 다음 세션 추천과 리포트에 실제 반영된다.
- AI·네트워크·외부 SDK가 없어도 전체 핵심 흐름이 이어진다.
- 사용자에게 반복해서 돌아올 실용적 이유가 생긴다.

### 제품 실패

- 체중 감량·칼로리 제한이 메인 가치처럼 보인다.
- `안 먹기`만 성공으로 집계한다.
- 추천 전에 가입·결제·긴 설문을 요구한다.
- 민감한 순간에 캐릭터·밈·결제로 압박한다.
- 데이터가 쌓여도 다음 추천이 달라지지 않는다.

## 12. 주요 가설과 검증 순서

| 우선순위 | 가설 | 최소 검증 |
|---|---|---|
| 1 | 사용자는 배달앱 직전 90초 이내 개입을 받아들인다 | 첫 추천 소요시간과 첫 세션 완료율 |
| 2 | 먹는 선택을 존중하면 결과 기록과 재방문이 늘어난다 | 선택 유형별 결과 기록률·D7 |
| 3 | 세이브 메뉴 재사용이 일반 AI 추천보다 반복 가치를 높인다 | 세이브 메뉴 재추천 노출 대비 선택률 |
| 4 | 주간 리포트가 비난 없이 패턴을 보여주면 재방문한다 | 리포트 조회 후 7일 내 다음 세션률 |
| 5 | BERRY MINT DIARY 캐릭터가 신뢰를 해치지 않고 친밀감을 만든다 | 첫 세션 완료, 캐릭터 선호, 안전 관련 신고 |
| 6 | 선별된 오늘의 레시피가 충동이 없는 날에도 재방문 이유를 만든다 | 피드 조회→저장·조리 시작, 레시피 사용자 D7 value retention |

지표의 계산식과 가드레일은 [METRICS.md](./METRICS.md)를 따른다.
