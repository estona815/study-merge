# DAESIN 수익화 계약

- 문서 상태: Launch MVP v0.1
- 오너: Product & Growth
- 기준일: 2026-07-14
- 통화 기본 표시: 대한민국 스토어의 현지 통화

## 1. 수익화 원칙

1. 핵심 충동 개입은 무료로 무제한 제공한다.
2. `먹지 않음`이나 칼로리 제한을 유료 성과로 판매하지 않는다.
3. 진행 중 충동 세션과 sensitive mode에서는 paywall을 노출하지 않는다.
4. 추천의 안전성, 알레르기 필터, 데이터 삭제, 구독 복원은 결제 여부와 무관하다.
5. Pro는 더 깊은 개인화, 패턴 해석, 편의와 표현 확장에 과금한다.
6. 실제 스토어에서 조회한 가격·기간·trial 조건을 source of truth로 사용한다.
7. 가짜 카운트다운, 숨은 닫기, 죄책감, 강제 연속성은 사용하지 않는다.

## 2. Launch 상품 구조

단일 entitlement `daesin_pro`를 월간·연간 상품으로 제공한다. 영구 구매와 여러 Pro 등급은 Launch MVP에서 제외한다.

| 기능 | Free | Pro |
|---|---|---|
| 충동 개입 세션 | 무제한 | 무제한 |
| 세 가지 선택·5분 타이머 | 포함 | 포함 |
| 규칙 기반 fallback | 포함 | 포함 |
| AI 코칭 | 기본 개인화 | 장기 행동·시간대 패턴을 반영한 고급 개인화 |
| 오늘의 대신 레시피 | 하루 3~5개, 출처·안전·영양 신뢰도와 현재 선호 기반 기본 개인화 | 장기 선택·저장·조리 이력을 반영한 고급 랭킹 |
| 결과 기록 | 기본 기록·주간 요약 | 상세 월간 리포트와 비교 패턴 |
| 세이브 메뉴 | 5개 | 무제한 |
| 말투 | 담백·친구, 밈 낮음 | 전체 밈 강도와 추가 카피 팩 |
| 테마·대신이 | 기본 테마·기본 스킨 | 고급 테마·추가 대신이 스킨 |
| 알림 | 사용자가 정한 기본 알림 | 충분한 데이터가 있을 때의 시간대 패턴 알림 |
| 공유 카드 | 기본 템플릿 | 테마·스티커·레이아웃 커스터마이징 |
| 데이터 내보내기·삭제 | 포함 | 포함 |
| 저자극 보기·칼로리 숨김 | 포함 | 포함 |
| 알레르기·식이 제한 | 포함 | 포함 |

### Launch에서 판매 문구에 넣지 않을 기능

- 실시간 음성 AI
- 음식·냉장고 사진 인식
- 편의점 실시간 상품 데이터
- 위젯
- 배달앱 감지

위 기능은 P1이므로 구현·검증되기 전에는 Pro 혜택, “곧 제공”, 절약 가치에 포함하지 않는다.

## 3. 무료 한도 계약

- `free_save_meal_limit = 5`
- 사용자는 한도 안에서 항목을 자유롭게 편집·삭제할 수 있다.
- 여섯 번째 세이브 메뉴 추가 시 기존 데이터를 잠그지 않는다.
- 사용자가 Pro로 구독했다가 Free로 돌아와 5개를 초과해도 기존 항목을 삭제하지 않는다. 조회·선택은 유지하고 새 추가만 제한한다.
- Free 사용자의 과거 기록과 데이터 내보내기는 구독 만료로 숨기지 않는다.

이 한도는 내부 제품 가설이며 remote config로 변경할 수 있다. A/B 테스트로 안전·신뢰 기능을 제한하지 않는다.

## 4. Paywall eligibility와 노출 시점

### 자동 노출 가능 조건

아래 중 하나를 충족하고 금지 조건에 해당하지 않을 때만 가능하다.

- 완료된 의식적 선택 세션 3회 이상
- 첫 주간 리포트를 확인함

자동 paywall은 홈으로 완전히 돌아온 뒤의 다음 비핵심 전환에서만 노출하며 **최대 7일 1회**로 제한한다.

### 사용자 의도 기반 노출

최소 1회 세션 완료 후 사용자가 아래 기능을 명시적으로 누르면 paywall로 이동할 수 있다.

- 여섯 번째 세이브 메뉴 추가
- 상세 월간 리포트 열기
- Pro 테마·스킨·공유 카드 선택
- 패턴 기반 알림 설정

이 경우 `Pro 기능` 라벨과 현재 잠긴 이유를 탭 전에 보여준다.

### 절대 금지 조건

- 첫 충동 개입 완료 전
- 음식 입력부터 결과 저장까지 진행 중인 세션
- sensitive mode 활성 또는 긴급 지원 안내 직후
- 데이터 삭제·구독 복원·결제 오류 처리 중
- 네트워크 오류를 해결하기 위한 fallback 직후
- 앱이 백그라운드에서 복귀해 타이머를 복원하는 순간

## 5. Paywall 정보 구조

1. `더 깊게 개인화되는 대신`이라는 가치 제목
2. 현재 실제 제공 중인 Pro 혜택 3~5개
3. 월간·연간 상품 카드와 스토어가 반환한 현지 가격
4. trial이 있을 때 시작일·종료일·그 뒤 청구액
5. 명확한 기본 CTA
6. 항상 보이는 닫기와 `구독 복원`
7. 자동 갱신, 해지 방법, 약관, 개인정보 링크

금지 카피 예시:

- “Pro가 아니면 또 실패해요”
- “오늘만 90% 할인”처럼 검증되지 않은 긴급성
- “더 적게 먹는 사람들의 선택”
- “이 기능 없이는 야식을 막을 수 없어요”

허용 카피 예시:

- “내 시간대와 실제 선택을 더 오래 기억해요.”
- “세이브 메뉴와 패턴 리포트를 제한 없이 사용해요.”
- “핵심 충동 브레이크는 무료로 계속 사용할 수 있어요.”

## 6. 가격 실험안

아래 가격은 확정 소비자가가 아니라 대한민국 스토어용 **내부 가설**이다. 스토어 상품 승인과 세금·가격 티어 확인 뒤 실제 표시값으로 교체한다.

| 셀 | 월간 가설 | 연간 가설 | 표시 규칙 |
|---|---:|---:|---|
| A — 접근성 | ₩7,900 | ₩49,000 | 월간과 연간을 동등하게 선택 가능 |
| B — 프리미엄 | ₩9,900 | ₩59,000 | 기능은 A와 동일, 가격 인식만 검증 |

연간 절약률은 `1 - annual_price / (monthly_price × 12)`로 런타임 계산하고, 현지 스토어 가격이 모두 정상 로드됐을 때만 표시한다. 반올림 규칙과 세금 포함 여부를 스토어 문구와 맞춘다.

### 실험 순서

1. **메시지 검증:** 단일 가격에서 `개인화` 대 `패턴·리포트` 가치 문구를 비교한다.
2. **trial 검증:** 동일 가격·paywall에서 연간 7일 trial과 trial 없음 셀을 비교한다.
3. **가격 검증:** 메시지와 trial 조건을 고정한 뒤 A/B 가격 셀을 비교한다.

가격과 trial을 동시에 바꿔 원인을 섞지 않는다. 한 프로필에는 하나의 가격 셀만 영구 할당하고 계정 연결 뒤에도 유지한다.

### 실험 성공 판단

- 1차: 활성화 사용자 기준 D30 유료 전환 또는 30일 실현 순수익
- 진단: paywall→trial, trial→paid, 연간 선택률
- 가드레일: 환불, 결제 문의, paywall 후 핵심 세션 감소, 알림·앱 이탈
- 최소 100회 적격 paywall 노출 전에는 작은 전환 차이를 승리로 선언하지 않는다.
- 표본 수 산정과 최소 검출 효과를 실험 시작 전에 별도로 기록한다.

## 7. Remote config와 상품 키

코드와 카피에 가격을 직접 고정하지 않는다.

| 키 | 기본값 | 용도 |
|---|---:|---|
| `monetization.free_save_meal_limit` | `5` | Free 세이브 메뉴 추가 한도 |
| `monetization.auto_paywall_min_sessions` | `3` | 자동 노출 최소 완료 세션 |
| `monetization.auto_paywall_cooldown_days` | `7` | 자동 노출 간격 |
| `monetization.weekly_report_unlocks_paywall` | `true` | 첫 리포트 뒤 eligibility |
| `monetization.offering_id` | 환경별 값 | RevenueCat 또는 대체 provider offering |
| `monetization.paywall_message_variant` | `personalization` | 가치 카피 실험 |
| `monetization.price_test_cell` | 서버 할당 | 가격 실험 셀; 클라이언트 임의 변경 금지 |

가격, trial, product identifier는 provider offering과 App Store·Google Play product metadata에서 불러온다.

## 8. Entitlement 상태 계약

| 상태 | 앱 동작 |
|---|---|
| `unknown` | Free 기능을 안전하게 제공하고 Pro 구매를 확정으로 표시하지 않음 |
| `free` | Free 한도 적용 |
| `trial` | Pro 제공, 종료일 표시 가능 |
| `active` | Pro 제공 |
| `grace_period` | Pro를 유지하고 결제 문제를 비난 없이 안내 |
| `expired` | 기존 데이터 보존, 새 Pro 작업만 제한 |
| `billing_issue` | provider 정책에 따라 grace 처리, 중복 구매 유도 금지 |

- 클라이언트 캐시는 오프라인 UX를 위한 힌트일 뿐 최종 권한 원장이 아니다.
- 앱 시작 시 외부 SDK 초기화가 실패해도 앱이 종료되지 않는다.
- 구매 완료와 entitlement 활성화가 불일치하면 결제 성공을 반복 유도하지 않고 복구 화면을 제공한다.
- iOS·Android 모두 `구독 복원`을 설정과 paywall에서 접근 가능하게 한다.

## 9. 취소·환불·복원 경험

- 취소 경로를 숨기지 않고 해당 스토어 관리 화면으로 연결한다.
- 해지는 실패가 아니며, 남은 이용 기간과 Free에서 유지되는 기능을 명확히 안내한다.
- 해지 설문은 선택이며 한 화면·한 문항을 넘기지 않는다.
- 환불 가능 여부와 처리는 스토어 정책에 따르며 앱이 승인 여부를 단정하지 않는다.
- 복원 실패 시 계정·스토어 계정·네트워크 확인 순서를 제공하고 지원 경로를 남긴다.

## 10. 수익 모델 계산

실제 transaction 원장을 기준으로 아래를 계산한다.

```text
gross_revenue = verified_store_transactions_sum
net_revenue = gross_revenue - store_fees - taxes - refunds
ARPPU = net_revenue / unique_paying_profiles
paid_conversion_30d = activated_profiles_paid_within_30d / activated_profiles_eligible_30d
voluntary_churn = voluntarily_expired_subscriptions / renewable_subscriptions_at_period_start
```

초기에는 LTV, CAC payback, 매출 전망을 단정하지 않는다. 최소 두 번의 유료 갱신 주기와 채널별 획득비 데이터가 생긴 뒤 산출한다.

## 11. Launch 수익화 QA

- 스토어 현지 가격과 paywall 가격이 일치한다.
- trial 종료 뒤 청구액과 주기가 CTA 근처에 보인다.
- 월간·연간 모두 선택 가능하며 사전 선택이 시각적으로 명확하다.
- 닫기, 복원, 약관, 개인정보 링크가 작동한다.
- 첫 세션·진행 중 세션·sensitive mode에서 paywall 이벤트가 0건이다.
- 구매 취소, 결제 실패, 오프라인, pending, grace period를 테스트한다.
- 구독 만료 뒤 기존 세이브 메뉴와 기록이 삭제되지 않는다.
- iOS와 Android에서 실제 sandbox 상품으로 구매·복원한다.
- mock subscription은 실제 결제 검증과 구분해 보고한다.

## 12. 출시 판정

다음 중 하나라도 충족하지 못하면 결제 기능을 운영 출시하지 않는다.

- 실제 상품 metadata와 표시값 일치
- 구매·복원·만료·환불 상태 처리
- 민감 모드와 핵심 세션 paywall 차단
- 구독 없이 핵심 흐름 완주
- 약관·개인정보·자동 갱신 고지
- 분석 이벤트에 가격 문자열만이 아닌 offering·product ID 기록
