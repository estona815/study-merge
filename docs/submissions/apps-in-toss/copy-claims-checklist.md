# Apps In Toss Copy Claims Checklist

작성 기준: 2026-06-12 KST

## Approved Positioning

Use this framing across Apps in Toss console fields, app detail text, screenshots, onboarding, CTA labels, paid feature copy, and support text:

- Installation-free 3분 beauty self-care miniapp
- Routine guide and timer
- Local routine log and optional photo note
- User-controlled reminders, only if supported in the final build
- Browser or miniapp reference route display, not diagnosis or outcome prediction
- Local-first data handling unless final SDK/API integration changes it

## Copy Review

| Surface | Required Check | Status |

| First screen CTA | Clearly starts the routine and does not overpromise | To verify before submission |

## Allowed Wording Direction

- "토스 안에서 바로 여는 3분 괄사 루틴"
- "뷰티 셀프케어 타이머"
- "단계별 루틴 안내"
- "로컬 기록"
- "사용자가 선택한 사진 메모"
- "참고 동선을 화면에 표시"
- "데이터는 현재 브라우저 또는 미니앱 환경에 저장"
- "불편하면 즉시 중단하고, 우려되는 상태는 전문가와 상담"

## Avoid Wording Direction

- Appearance change promises
- Before/after proof language
- Stronger claim for paid users
- Countdown pressure that hides paid terms
- Face guide language that sounds like judgement
- Medical, diagnosis, treatment, guaranteed result, or before/after proof language
- Claims about server-side protection or sync unless implemented and reviewed
- Any claim that differs from the final Apps in Toss SDK/API behavior

## Final Review Steps

Before requesting Apps in Toss review, check:

- Console app information
- App detail page text
- Screenshot captions
- First-run screen
- Timer screen
- Completion screen
- Settings/privacy/support screen
- Permission prompts
- Paid feature labels, if used
- Ad reward copy, if used
- Hosted privacy/support pages
